# 💳 Richman — 스마트 금융 통합 플랫폼

> 소비 분석 · 주식 · 크립토를 하나의 흐름으로 연결하고, AI 챗봇이 금융 생활 전반을 해석해주는 스마트 금융 플랫폼

---

## 🧭 서비스 소개

Richman은 단순 가계부나 시세 조회 앱이 아닙니다.  
사용자의 **실제 금융 데이터를 통합 관리**하고, AI가 개인화된 인사이트를 제공합니다.

```
소비 데이터 수집 → 패턴 분석 → 주식/크립토 조회 → 감성 분석 → AI 챗봇 인사이트
```

---

## ✨ 핵심 기능

### 🧾 소비 분석
- **소비 캘린더** — 날짜별 지출 시각화, 무지출 데이 배지
- **소비 데이터 분석** — 카테고리별 도넛 차트, 고정 지출 추적, AI 소비 리포트
- **스마트 정산** — N빵 정산 등록 후 실제 소비에 자동 반영

### 📈 주식
- **종목 검색 & 자동완성** — 국내(KRX) · 해외(NASDAQ, NYSE) 지원
- **기술 지표 시각화** — 이동평균선(MA), 볼린저 밴드 차트 오버레이
- **관심 종목 & 포트폴리오** — 보유 수량/단가 입력 → 수익률 자동 계산
- **AI 예측 히스토리** — 예측가 vs 실제 종가 비교, 오차 지표(MAE·RMSE) 공개

### 🪙 크립토
- **실시간 시세 대시보드** — Upbit API 기반 현재가 · 등락률 · 거래량
- **Social Buzz 지표** — 뉴스 언급 빈도 + 거래량으로 코인 관심도 수치화
- **감정 지표** — GPT 기반 뉴스 감성 분석 (긍정/중립/부정)

### 🤖 AI 통합 챗봇
사용자의 실제 데이터를 컨텍스트로 주입해 개인화된 금융 인사이트 제공

| 소비 | "이번 달 배달 앱 지출이 전월 대비 34% 증가했어요." |

#### 🔍 느낀 점 & 트러블슈팅

**SSE 406 오류**  
DRF `APIView` 기반으로 SSE 엔드포인트를 구현했을 때 406 Not Acceptable 오류가 반복 발생했습니다. DRF가 `text/event-stream` Content-Type을 처리하지 못하는 것이 원인이었고, Django 기본 `View`로 교체하여 해결했습니다.

**EventSource JWT 인증 불가**  
브라우저 `EventSource`는 커스텀 헤더를 지원하지 않아 JWT 토큰을 전달할 수 없었습니다. Buzz 스트림 엔드포인트는 공개 데이터 특성상 `AllowAny`로 처리하는 방향으로 결정했습니다.

**폴링 시 DOM 깜빡임**  
10초마다 코인 목록 전체를 교체하면 화면이 깜빡이는 문제가 있었습니다. 배열 전체를 재할당하는 대신 기존 객체의 필드만 직접 업데이트하는 방식으로 변경하여 해결했습니다.

### 💡 금융 상품 추천 알고리즘 (주가 예측)

이동평균선(MA) 기반 가중 평균 예측 모델을 구현했습니다.

```python
# 예측 공식
predicted_price = MA5 × 0.6 + MA20 × 0.4
```

- **MA5 (단기, 가중치 0.6)**: 최근 5일 종가 평균 → 단기 추세 반영
- **MA20 (중기, 가중치 0.4)**: 최근 20일 종가 평균 → 중기 추세 반영
- 단기 추세에 더 높은 가중치를 부여해 최신 시장 흐름을 우선 반영
- 예측 결과는 DB에 저장되고, 예측일 경과 후 실제 종가와 자동 비교하여 MAE(평균 절대 오차율) 및 성공률(±2% 이내) 계산

또한 팀 협업 과정에서 공용 파일(NavBar, router, axios)을 수정할 때 항상 팀원 코드를 먼저 확인하는 습관을 들인 것이 merge conflict를 최소화하는 데 큰 도움이 됐습니다. 혼자 개발할 때와 달리, 팀원의 코드 스타일과 구조를 먼저 파악하고 거기에 맞게 내 기능을 녹여내는 경험이 실무에서의 협업이 어떤 것인지 조금이나마 느낄 수 있게 해주었습니다.

SSAFY 1학기를 마무리하는 프로젝트로서, 배운 기술들을 실제 서비스로 구현해보는 값진 경험이었습니다.

### 💡 금융 상품 추천 알고리즘 (금융 상품 추천)

가중치 기반 유사도(`weighted-similarity`) 및 콘텐츠 기반 필터링 모델을 구현했습니다.

```python
# 최종 추천 점수 (Final Score) 산출 공식
Final Score = Base Rate Score × α (관심자산 가산점) × β (성향 가중치)

1. Base Rate Score (체급 점수): (기본 금리 × 0.4) + (최고 우대 금리 × 0.6)
2. α (관심자산 가산점 계수): 온보딩 설문에서 [예/적금] 선택 시 α = 1.5 (50% 보너스 점수 부여)
3. β (투자성향 가중치 계수): 
   - 안정 추구형: β = 1.2 (안전 자산 우대)
   - 중립형 (페르소나 김싸피 적용): β = 1.0 (인위적 가감산 없는 정석 큐레이션)
   - 공격 투자형: β = 0.8 (예적금 점수 감산 후 주식/크립토 비중 확대)
🤖 생성형 AI 활용 및 개발 보조 내용

특히, 가계부 통계를 왜곡하는 가장 큰 주범인 '공동 지출(N빵)'을 발라내기 위해 스마트 정산 시스템을 설계하고 구현하는 과정이 가장 도전적이었습니다. 정산 대기 상태값을 관리하고 이체 완료 시 환급액을 제외한 '순수 실지출'만 발라내어 Chart.js 도넛 차트에 실시간으로 리렌더링하는 UX를 다듬으며 데이터 정제의 중요성을 깊이 깨달았습니다.

또한 모노톤 하드엣지라는 명확한 디자인 컨셉 하에 프론트엔드 CSS 가이드라인을 공유하고, TheFooter.vue와 NavBar.vue 등 공용 레이아웃 컴포넌트에 브랜드 타이포그래피 로크업(Richman.)을 엄격히 통일하는 과정에서 UI/UX의 일관성이 주는 완성도를 체감했습니다. 각자의 브랜치(feature/Koo-KAN-36-consumption)에서 지라 티켓 기반으로 소통하며 휴먼 에러를 줄이고 단 한 건의 대규모 머지 충돌 없이 배포를 완료한 경험은 개발자로서 협업 시야를 넓혀준 값진 자산이 되었습니다.
